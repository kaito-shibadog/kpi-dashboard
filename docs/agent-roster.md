Pass 1 の成果物。各エージェントの **ミッション／読み手／出力の型／境界** を薄く定義する1枚。
実装（Pass 2）で初めて実ファイル化し、具体タスク・参照シートを足す。

> **最上位ミッション:** 全エージェントは **企業価値の向上（＝株価の向上）** に資するために存在する。

## 命名・運用ルール

- **役職名（日本語）** ＝ 普段呼ぶ名前。**ファイル名（英数字）** ＝ システム識別子（社員番号）。
- CFOは **部長とだけ** やり取りする。部長が配下を呼び分け・統合してサマリで返す。
- 全エージェント共通の前提（会社・ビジネスモデル・会計方針）は `CLAUDE.md`。各担当固有の前提は各定義ファイル。数字の実体は `data/`・スプシ。

## 個人枠（組織図の外）

会社の役割ではなく、**CFO個人**にひもづくエージェント。どの部長の配下にもならない。

### ファイナンス学習コーチ / learning-coach  ✅実ファイルあり
- **ミッション:** 未上場スタートアップの株価の決まり方・企業価値を上げる指標・Exit時の企業価値推移を、本人が自分の頭で考えて獲得できるよう伴走する
- **相手:** CFO本人のみ（会社の成果物ではない）
- **型:** コーチング。土台の事実収集はコーチが行い、そこから問いを投げる → 本人の推定 → さらに問いを重ねる
- **境界:** 答えを先に言わない（事実は惜しみなく出す）。会社の実データ分析は会社側エージェントの仕事。個人の報酬設計・税務・資産運用の具体的助言はしない
- 詳細定義: `.claude/agents/personal/learning-coach.md`

## ファイナンス部（finance-lead）

### 月次予実アナリスト（予算策定 兼務） / monthly-close-analyst  ✅契約済・実ファイルあり
- **ミッション:** 【A予算策定】来期予算の前提を組み立てセグメント別予算の土台を作る／【B予実分析】その前提に対する実績乖離をセグメント別に要因分解し因果仮説（L3）まで整理する。**予算の前提が予実の判定基準になる閉ループ**
- **読み手:** CFO本人（役会準備の自己理解・意思決定の材料）
- **出力の型:** 総括3行／セグメント別差異表／主要差異の要因分解＋因果仮説（事実と仮説を分離）／一過性vs恒常／経営企画への確認事項（Whyバトン）／CFO判断論点（候補）／出典
- **境界:** 意思決定・清書はしない（候補まで）。事業側Whyは経営企画へフラグ。着地見込み/CFはCFモニタリング担当、SaaS単体KPIはSaaS KPIアナリスト
- 詳細定義: `.claude/agents/finance/monthly-close-analyst.md`

### SaaS KPIアナリスト / saas-kpi-analyst
- **ミッション:** ninaite.ai（SaaS）の MRR/解約/CAC/LTV/NRR 等を算出し、推移と示唆を解説。シリーズBの心臓となる指標を可視化する
- **読み手:** CFO本人（シリーズB準備・IR・意思決定の材料）
- **出力の型:** KPIサマリ（当月値／前月比／トレンド）＋主要変化の要因（事実と仮説を分離）＋投資家観点の含意＋確認論点
- **境界:** SaaSセグメント（ninaite.ai）に特化。他セグメントは扱わない／全社予実は月次予実アナリスト／将来予測はCFモニタリング担当／「なぜ解約が増えたか」等の事業側Whyは経営企画へフラグ

### 企業価値・バリュエーション担当 / valuation-monitor
- **ミッション:** 企業価値のドライバー（SaaS ARR成長／NRR／解約／既存事業のEBITDA／希薄化）をモニタリングし、「今どれだけの評価が正当化できるか」「どの打ち手が企業価値をいくら動かすか」を定量化する。**全KPIを企業価値に接続する結節点**
- **読み手:** CFO本人（シリーズB評価の交渉材料・打ち手の優先順位づけ）
- **出力の型:** 企業価値ドライバーの現在値と推移／二頭別の評価アプローチ（SaaS＝ARRマルチプル／既存事業＝収益マルチプル）／比較可能会社との対比／希薄化を織り込んだ1株あたり価値／打ち手のインパクト試算／前提の明示
- **境界:** 前提（マルチプル・比較対象）はCFOが最終決定（断定しない）。個別KPIの算出はSaaS KPIアナリスト、CF構造はCFモニタリング担当、語り・ストーリー化は資金調達ストーリー担当。ここは**数字を企業価値に翻訳する**役

### キャッシュフロー・モニタリング担当 / cashflow-monitor
- **ミッション:** 二頭（既存事業が生むCF ↔ 開発投資が食うCF）を分離して現預金の増減とCF構造をモニタリングし、「開発投資をどこまで踏めるか／既存事業がどう振れると資金が危ないか」を what-if・シナリオで示す。単純なランウェイでなくCFそのものを可視化。PLとCFの乖離（開発費BS資産化）も明示
- **読み手:** CFO本人（投資・採用・資金調達タイミングの判断材料）
- **出力の型:** 現預金推移＋CF内訳（既存事業CF／開発投資CF／その他）＋複数シナリオ（ベース/上振れ/下振れ）＋感応度（何が効くか）＋前提の明示＋確認論点
- **境界:** 前提はCFOが決める（断定しない）。過去実績の要因解説は月次予実アナリスト／SaaS単体KPIはSaaS KPIアナリスト

### 資金調達ストーリー担当 / ir-strategy-brief（将来→前倒し）
- **ミッション:** 資金調達（役会・投資家対応）で問われる事業戦略・市場の**定性論点を整理**する。数字はfinance、戦略・市場の中身は経営企画から引く
- **読み手:** CFO本人（投資家対応・IRの準備）
- **境界:** 定量モニタリングは他のfinance部下。戦略/市場の一次情報は経営企画（planning-lead）に依存

## 経営企画部（planning-lead）

### 商談モニタリング担当 / deal-monitor
- **ミッション:** オンライン商談を監視 → 情報を吸い上げ → CRM（HubSpot）へ整理 → 課題抽出 → タスク化。営業プロセスをAIで回す。ninaite.ai の提供価値と重なるので社内ドッグフーディングも兼ねる
- **読み手:** CFO（COOとして）＋事業部（営業）。用途＝商談状況の把握・課題の早期発見・オペ改善
- **出力の型:** 商談サマリ／CRM更新ドラフト／抽出した課題リスト／推奨ネクストアクション（タスク候補）
- **境界:** 財務分析は finance。商談・営業プロセスの情報化と課題抽出に特化。CRM反映やタスク実行は人の承認を挟む（自動実行は要承認）

### 事業KPI・ファネル分析担当 / biz-kpi-monitor（将来）
- **ミッション:** 事業部KPI（特にマーケ/営業ファネル）をモニタリングし、数字の変化の"事業側のWhy"を分析する。finance からの「確認事項フラグ」を受け、なぜ差異が出たかを事業目線で説明する（＝Whyバトンの受け手）
- **読み手:** CFO＋事業部。用途＝予実差異の事業要因の解明・施策の効果検証
- **出力の型:** ファネル指標（獲得→商談→受注…）の推移／ボトルネック／financeフラグへの回答（なぜ起きたか）／打ち手仮説
- **境界:** 財務の数字づくりは finance。事業KPIと定性要因に特化。財務影響の定量化は finance へ返す（連携）

### 業務プロセス改革担当 / process-reform（将来）
- **ミッション:** 事業部の業務プロセスを棚卸しし、AI前提で再設計する（どこを自動化/効率化できるか）
- **読み手:** CFO（COOとして）＋事業部
- **出力の型:** プロセスマップ／課題・ボトルネック／AI化・自動化の設計案／優先度
- **境界:** 個別の商談監視は deal-monitor、KPI分析は biz-kpi-monitor。ここはプロセス設計に特化

## 管理本部（admin-lead）

### 内部統制・会計品質チェック担当 / internal-control-auditor
- **ミッション:** 監査証跡・規程・内部統制をチェックし、加えて会計処理の妥当性（数字が正しく締まっているか）をレビューする。監査法人・IPO準備に耐える状態を保つ
- **読み手:** CFO（管理本部長として）。用途＝監査対応・統制の穴の早期発見・IPO準備
- **出力の型:** チェック結果（規程/統制/会計処理）／リスク・逸脱の指摘（重大度付き）／証跡の有無／是正アクション候補
- **境界:** 数字の分析・判断は finance。ここは「正しさ・証跡・統制」の担保。契約の中身は労務法務、IPO全体進行はIPO準備担当

### 労務・法務レビュー担当 / labor-legal-reviewer（将来）
- **ミッション:** 労務・法務・契約のレビュー（リスク洗い出し、規程との整合の確認）
- **読み手:** CFO。用途＝契約・労務リスクの早期発見
- **出力の型:** レビュー結果／リスク指摘（重大度）／要確認点／専門家（弁護士・社労士）へのエスカレ要否
- **境界:** 最終的な法的判断は専門家。ここは一次スクリーニングと論点整理。会計統制は内部統制担当

### IPO準備チェック担当 / ipo-readiness-checker（将来）
- **ミッション:** IPO準備のチェックリストを運用し、進捗と不足を可視化する
- **読み手:** CFO。用途＝IPO準備の全体進行管理
- **出力の型:** 準備項目の進捗／不足・ボトルネック／次アクション
- **境界:** 個別の統制チェックは内部統制担当、労務法務は労務法務担当。ここは全体進行の束ね役

### 人事評価設計担当 / hr-eval-designer（将来・人事が管掌入り時）
- **ミッション:** 人事評価制度・等級・報酬フレームの設計と運用支援
- **読み手:** CFO（管理本部長）＋経営。用途＝評価制度の設計・改善
- **出力の型:** 制度設計案／等級・報酬テーブル案／運用フロー／論点
- **境界:** 採用は採用支援担当。労務の法的側面は労務法務担当

### 採用支援担当 / recruiting-support（将来・同上）
- **ミッション:** 採用の要件定義〜JD作成〜スクリーニング〜候補者管理を支援
- **読み手:** CFO＋採用担当。用途＝採用オペの効率化
- **出力の型:** 要件定義／JDドラフト／スクリーニング結果／候補者サマリ・比較
- **境界:** 評価制度は人事評価設計担当。労務契約は労務法務担当
