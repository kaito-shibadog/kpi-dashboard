## BPOの2分類（(X)/(Y)）と判定基準

同じ「BPO」でも企業価値への効き方が**正反対**なため、必ず区別する。

| | (X) 労働集約型 | (Y) コアを握る型（＝④） |
|---|---|---|
| 対象 | 地方零細（Tier3） | Tier1〜2 |
| 中身 | オペレーションの巻き取り | 制度設計・モニタリング |
| LTV | 伸びにくい | ワークフローに入り込む |
| 企業価値への影響 | **マルチプルを下げる** | **上げうる** |

**一次判定基準 ＝ 課金単位**（契約書を見れば一意に決まり、運用で揺れない）

- **外国人数 単位の課金 → (X)**：工数が人数に比例し、労働集約と構造的に結合している
- **事業所 単位などの課金 → (Y)**：工数が人数に比例しない＝仕組みの提供

補助的な説明軸（判定には使わず、説明に使う）:
- オペレーションではなく「仕組みを作り運用する」サービスか
- データ取得と、それを踏まえた顧客の人事改善に寄与するか

## 「経営ダッシュボード」スプシの構造（2026-07-20 実地調査）

会計年度は **11月始まり10月締め**（10月決算）。月次。23個の表ブロックが1ファイルに同居。

**主な内容:** 経営サマリ／KPI推移（業種別）／PL：統合（実績+見込・予算・実績+予算の3版）／PL：直接雇用・派遣（各3版）／CF：統合／資金繰り明細／開発費明細／人材紹介 案件明細／支援委託費 明細

### ⚠️ 個人情報（PII）の所在 — エージェントの読み取り範囲から除外すること

- **人材紹介 案件明細** / **支援委託費 明細**: 外国人従業員の**実名と勤務先法人名が数百件**
- **開発費明細**: 社内開発メンバーの実名

→ エージェントには **PL／CF／KPI推移のブロックのみ**を読ませ、上記の明細ブロックは**除外**する。
　 生データを保存する必要が生じた場合は `data/private/`（gitignore済）に限定する。

### 機械パース上の既知の難所

1. タブ名が取得できず、ブロック識別はヘッダー文字列に依存。しかも `PL：<統合>` がセグメント別シートでも同じ文字列（末尾の `直接雇用従事人数`／`派遣従事人数` 行で判別する）
2. 1シートに複数表が縦積みで、月次ヘッダーが繰り返される
3. セグメントラベルは結合セル由来でグループ先頭行にしか入らない → **前方補完が必須**
4. 小計行（`売上高合計` `営業利益` 等）が明細と同じ列構造で混在 → **除外しないと二重計上**
5. 負数が `\-4,940,546` 形式（バックスラッシュ＋カンマ）、`#DIV/0!` がそのまま残存
6. 時間値が `<span type="duration">` のHTMLタグ
7. 年なし月ヘッダー（`11月…10月`）→ 年度跨ぎの解決ロジックが必要
8. 表記ゆれ: `営業利益(本社費用割賦後` は**閉じ括弧が欠落**／「本社経費」と「本社費用」がブレる
9. **売上側と原価側でセグメントラベル体系がズレている**（売上 `直接雇用(営業部門)` ↔ 原価 `直接雇用(札幌)`）
10. 同一科目名が部門ぶん重複 → 第1列のセグメントと組にしないと一意にならない

### 判明した構造上のギャップ（契約に影響）

- **前年PLが存在しない。** 前年比較は `<比較用昨年データ>` の KPI4項目（紹介人数／支援人数／派遣人数／派遣時間）のみ。
  → 「予算・前年の2軸」のうち**前年軸はこのシート単独では成立しない**（MF会計等からの別経路が必要）
- **「予算」が一意でない。** `修正前予算`／`修正後予算` が同一行の左右6ヶ月ずつで切り替わり、別途 `予算` 単独版もある
- **「実績」と「見込」の境界が列ヘッダーにしかなく、毎月動く。** データソースも `MF実績` と `業績管理表+CRM+販管費編集` で切り替わる
- **ninaite.ai がセグメントとして組まれていない。** 売上は `TSUNAGITEプラットフォーム`（入国マッチングfee／転職マッチングfee／SAAS利用料）という別名でほぼ空。
  実コストは**開発費明細でBS資産計上（ソフトウェア仮勘定）**に隔離され、セグメント損益に出てこない
- **本社費用割賦で営業利益が2種類**（割賦前／人数比例で配賦後）。配賦キーの従事人数は月次変動
