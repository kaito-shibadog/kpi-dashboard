## BPOの2分類（(X)/(Y)）と判定基準

同じ「BPO」でも企業価値への効き方が**正反対**なため、必ず区別する。

| | (X) 労働集約型 | (Y) コアを握る型（＝④） |
|---|---|---|
| 対象 | 地方零細（Tier3） | Tier1〜2 |
| 中身 | オペレーションの巻き取り | 制度設計・モニタリング |
| LTV | 伸びにくい | ワークフローに入り込む |
| 企業価値への影響 | **マルチプルを下げる** | **上げうる** |

**一次判定基準 ＝ 課金単位**（契約書を見れば一意に決まり、運用で揺れない）

- **外国人数 単位の課金 → (X)**：工数が人数に比例し、労働集約と構造的に結合している
- **事業所 単位などの課金 → (Y)**：工数が人数に比例しない＝仕組みの提供

補助的な説明軸（判定には使わず、説明に使う）:
- オペレーションではなく「仕組みを作り運用する」サービスか
- データ取得と、それを踏まえた顧客の人事改善に寄与するか

## データ設計の要件（今から仕込む）

- **契約・売上データに「課金単位（外国人数／事業所）」のフラグを持たせる。**
  ④が未分離の今のうちに仕込むことで、(Y)が立ち上がった時に**過去に遡って分離できる**。
  これを怠ると「分けたいが過去データが混ざっていて分けられない」状態になる（経路依存）。
