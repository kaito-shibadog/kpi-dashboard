# 企業価値ドライバーツリー（③ドライバーモデル）

4層アーキテクチャ（①源泉データ → ②セマンティック層 → **③ドライバーモデル** → ④エージェント群）の③。
最上位ミッション「**企業価値の向上（＝株価の向上）**」と、日々のKPIを接続する。
全エージェントが「自分はこのツリーのどのノードに効いているか」を言える状態にするための1枚。

## ツリー

```
1株あたり価値
├─ 企業価値（EV）
│   ├─ ■ 現在の収益価値
│   │    ├─ ninaite.ai（SaaS / MRR）  ← 登録外国人数 × 単価
│   │    ├─ 内製化支援（④）           ← ③のアダプションを可能にする層。事業所単位課金
│   │    ├─ 採用（spot売上）           ← 登録外国人数 × 転換率 × 単価
│   │    └─ 既存事業（直接雇用・派遣）EBITDA
│   ├─ ■ 将来のオプション価値（ブルーカラー向けフィンテック）
│   │    └─ 登録外国人数 × データの深さ
│   └─ ■ ネットキャッシュ（現預金 − 有利子負債）
└─ ÷ 株数（希薄化）
     ├─ 既発行株式／SO・潜在株式
     └─ 次回調達での新規発行 ← 既存事業CFで開発を賄うほど小さくできる
```

## 現フェーズの最重要ドライバー：登録外国人数

**アクティブ／継続ベースの登録外国人数**が、現フェーズで最も効くドライバー。

理由は、**現在の収益と将来のオプション価値の"両方の分母"に入る唯一のノード**だから（二重に効く）。

- **現在の収益**: MRRも採用spot売上も、いずれも外国人の人数ベースで課金される
- **将来の価値**: フィンテックTAMの母数。本質的な事業価値は `外国人の数 × データの深さ`

→ **今 登録者を増やすことは、今の収益を作る行為であると同時に、将来のデータ資産の"母数"を確保する行為**。

### 獲得単位は「個人」ではなく「企業・組合」

```
登録外国人数 ＝ 顧客社数 × 1社あたり雇用外国人数
```

| チャネル | 強み | 弱み |
|---|---|---|
| Tier1/2 事業会社 | 採用収益が厚い／ネームバリュー／クロスセル余地 | 意思決定が遅い／1社あたり人数に上限／育成就労は組合委託が残る |
| 支援機関・組合 | 意思決定が速い／支援人数増が先方の売上拡大＝インセンティブ一致／育成就労はこちら | 採用収益を出しにくい／アップセルが難しい |

> **CFO暫定見解（未決）:** フィンテック構想では登録経由の差は本質的でないため、早期トラクションを出す観点で**支援機関を優先**。

### ICPと閾値（ユニットエコノミクス）

- 業界標準の特定技能支援委託料: 外国人1人あたり**月1.5〜2.5万円**
- ninaite.ai: 1人あたり**月500円程度**
- 内製化に伴う自社人件費が発生するため、**コストメリットが出る損益分岐は雇用外国人数20人前後**

→ **プロダクトが内製化の手間を下げるほど閾値は下がり、TAMは下（Tier3側）に広がる。**
　 ただしTier3は現BPO事業の領域であり、カニバリを含む戦略判断になる（未決）。

## 第2軸：データの深さ（現時点で未定義）

事業の本質的ボトルネックは、外国人本人の**パーソナリティと信用情報**。その基盤データが最重要。
「質の高いデータ」とは、Excelで管理できる浅いデータ（在留期限・パスポート番号等）ではなく、
**AIでないと蓄積・解析できない暗黙知的なデータ**を指す。

取得の優先順（並べる基準は「**縦断データが意味を持つまでの時間**」）:

1. 就業開始後の職場での評価・日本語力の推移 ← 推移を見るのに物理的時間がかかるため最優先
2. 来日前の現地日本語学校での学習態度・テストの点数 ← 入国後パフォーマンスとの相関を見るなら早期着手が有利
3. 日本語試験・資格試験に受かるまでの時間
4. 給与情報・母国への送金情報

> ⚠️ **未解決の設計要件:** 最優先データ（1）は**雇用主側で発生する**。支援機関を優先するなら、
> 「支援機関経由でも雇用主経由と同等の深さのデータが取れる設計」が必須になる。

## 各エージェントの担当ノード

| ツリーのノード | 担当エージェント |
|---|---|
| 既存事業EBITDA・実績精度 | 月次予実アナリスト（monthly-close-analyst） |
| ARR／NRR／解約／ARPA／CAC | SaaS KPIアナリスト（saas-kpi-analyst） |
| ネットキャッシュ・希薄化 | キャッシュフロー・モニタリング担当（cashflow-monitor） |
| 新規獲得のドライバー（ファネル） | 事業KPI・ファネル分析担当（biz-kpi-monitor） |
| ツリー全体 → 企業価値への翻訳 | 企業価値・バリュエーション担当（valuation-monitor） |
| ツリー → 投資家への語り | 資金調達ストーリー担当（ir-strategy-brief） |

- 派遣セグメントの売却（企業価値のレバーとして能動設計するか／基盤ができた後の実戦テーマ候補）
